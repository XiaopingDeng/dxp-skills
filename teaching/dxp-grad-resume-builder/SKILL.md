# 本科应届生简历：撰写与评审

一个技能，两个角色。**先判定走哪条分支**——用户要一份新简历，还是要对已有的那份下判断。

| 分支 | 触发信号 | 产出 | 判据与细则 |
|------|---------|------|-----------|
| **A 撰写** | 给了个人信息 / JD / 培养方案，要一份简历 | `简历.md` + `简历.html` + `学习路线图.md` | [`references/compose-workflow.md`](references/compose-workflow.md) |
| **B 评审** | 丢来一份**已有**简历（PDF / 图片 / 文本），问"怎么样""有什么问题""帮我改" | `简历评价报告.html`，**原文档零改动** | [`references/review-rubric.md`](references/review-rubric.md) |

判不清时问一句：「你是要我帮你做一份新的，还是评一下你手上这份？」——猜错会让用户白等一轮。

**两分支共用**：`references/jd-analysis.md`（JD 拆解）、`references/training-program-mapping.md`（课程 → 证据）、`references/position-requirements-library.md`（JD 缺失时的岗位兜底）、`references/achievement-writing.md`（把职责写成成果的写法与英中投递惯例差异）。

---

## 分支 A：撰写

**Step 1 — 收齐四类输入**：基本信息、目标岗位、JD、培养方案。缺失项按 `position-requirements-library.md` 兜底并标注「以实际 JD 为准」，不要卡住用户。课程设计可直接当作项目种子。
→ 完成判据：四类输入要么来自用户，要么每项都标了兜底来源。

**Step 2 — 拆 JD、映射课程**：产出 `技能名 → 类别 → 优先级 → JD 原文依据` 清单，以及 `能力域 | 对应课程 | JD 匹配 | 掌握程度 | 简历落点` 对照表。匹配度打 ✅已覆盖 / 🔶部分 / ❌未覆盖。
→ 完成判据：JD 每个必需项都在对照表里出现过一次。

**Step 3 — 起草内容**：按 `resume-writing-guide.md` 的板块顺序写。每条经历用 STAR，动词开头、含量化。JD 要求但暂未掌握的能力标注 `（路线图中补强）`。
→ 完成判据：每条经历都有动词开头的 bullet，且至少一个数字。

**Step 4 — 写路线图**：对 🔶/❌ 项按 `roadmap-guide.md` 写学习卡（L0 入门 → L1 进阶 → L2 实战），每阶段带可量化的验收标准与产出物。
→ 完成判据：简历里每个 `（路线图中补强）` 都能在学习卡里找到对应条目。

**Step 5 — 渲染交付**：组装模型 JSON，跑 `python scripts/build_resume.py <model.json> --out <目录>`。回读产出，确认无占位残留、无编造数据。
→ 完成判据：三个文件都存在，且全文搜不到 `[?]`、`待补充`、`示例，请核对`。

## 分支 B：评审

指导老师的角色：**诊断 + 建议，不代笔**。原文档一个字节都不动——所有改动以「现 → 建议」对照形式给出。

**Step 1 — 取得原件并读全**：PDF 用 PyMuPDF 取文字层，**同时把页面渲染成图逐块看版面**。文字层顺序与视觉顺序可能不一致，只读文字层会误判。
→ 完成判据：能说出这份简历有几个板块、每个板块的实际顺序，以及页数。

**Step 2 — 定级问题**：按 `review-rubric.md` 的五个维度打分，再给每条问题定级 **P0 投递前必修 / P1 显著影响通过率 / P2 加分项**。
→ 完成判据：每条问题都有级别、位置（哪个板块）、以及为什么扣分。

**Step 3 — 给改法**：每条 P0/P1 都要有可直接替换的改写示范（保留学生真实信息，量化处留 `[?]` 让他自己填）。涉及学生本人才能确认的事（是否真做过某技术、团队规模、项目归属）标成**待核实**，不要替他填。
→ 完成判据：P0 与 P1 全部有「现 / 建议」对照；所有推测类内容都标了待核实。

**Step 4 — 预判追问**：列出面试官会就简历里的数字与技术细节追问的问题（每个量化指标都可能被问）。
→ 完成判据：报告里每个量化数字都能对应至少一个可能的追问。

**Step 5 — 出报告**：组装模型 JSON 的 `review` 字段，跑同一个 `build_resume.py` 渲染 `review.html`，再 `present_files` 交付。
→ 完成判据：报告含评分卡、分级清单、改写示范、追问预判、工时表；文末声明「未修改原简历」。

## 不变量（两分支都成立）

**真实性优先**——真实性优先于一切漂亮措辞。**红线**：不虚构实习公司、项目、获奖、证书、GPA、排名；用户未提供的经历用占位 + 引导语；基于真实课程或方向起草的描述必须标注「示例，请核对真实数据」，量化处留 `[?]`。竞争力来自**贴 JD 的针对性 + 清晰结构 + 量化表达**，不来自编造。没有经历就用「培养方案 + 路线图」证明学习力——这本身就是应届生的正确打法。

**一岗一版**——同一人投不同岗位生成不同版本。同一份简历可以通投，求职信不能；每版都要按 JD 关键词重写技能板块。

**证据锚点**——每条技能主张挂一个证据来源（哪个项目、哪门课、哪段实习），用项目/课程佐证"掌握程度"。表述分档：`熟练` / `了解` / `（路线图中补强）`，把最扎实的证据放在最强的那一档。避免整段"精通"。

**改动前先说**——评审分支不改原文档；撰写分支改用户已有的简历前，先说明改哪些、为什么改。

**交付后回读**——渲染完必须回读产出，确认无占位残留、无编造数据，再交付。
