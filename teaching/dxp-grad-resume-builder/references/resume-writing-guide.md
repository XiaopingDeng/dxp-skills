# 应届生简历撰写指南

本文件是各板块的**写法规范**。分支流程见 `compose-workflow.md`，把职责写成成果的动词强度与英中惯例差异见 `achievement-writing.md`，评审既有简历见 `review-rubric.md`。

## 一、最重要的原则：真实，不虚构

应届生简历可以有「竞争力」，**但绝对不能编造**。以下红线必须守住：

- 不虚构实习公司、项目、获奖、证书、GPA、排名。
- 用户未提供的经历，用「待补充」占位 + 引导语，绝不以假数据填充。
- 当用户给出课程 / 课程设计 / 比赛方向时，可基于真实信息**起草**描述性内容，但必须标注「示例，请核对真实数据后替换」，并把可量化的部分（月数、人数、指标）用 `[?]` 标出待填。
- 对确实空白的能力，不粉饰，而是导向学习路线图（见 `roadmap-guide.md`）去真实补齐。

> 简历的「竞争力」来自**针对性（贴 JD）**与**结构清晰 + 量化表达**，而不是造假。没有经历，就用「培养方案 + 自学路线图」证明学习力，这本身就是应届生的正确打法。

## 二、应届生标准板块顺序

按「与岗位相关度」从高到低排，弱项后置：

1. **求职意向 / 目标岗位**（顶部一行，明确）
2. **基本信息**（姓名、电话、邮箱、城市、政治面貌可选、GitHub/博客可选）
3. **教育背景**（学校、学院、专业、学历、入学-毕业时间、GPA/排名、核心课程）
4. **专业技能**（按 JD 要求重构，分「熟练 / 了解」两档，杜绝「精通」滥用）
5. **项目经历 / 实践经历**（课程设计、实训、比赛、个人项目，用 STAR + 量化）
6. **实习经历**（如有，放在项目之前；用真实信息）
7. **校园经历 / 学生工作**（干部、社团、志愿，体现软技能）
8. **获奖与证书**（奖学金、竞赛奖、语言/证书）
9. **自我评价 / 求职优势**（2-3 句，扣岗位，不写空话）

> 顺序可调：若实习很强，把「实习经历」提到「项目经历」前；若科研/论文突出，单列「科研经历」。

## 三、各板块写法

### 教育背景
- GPA ≥ 3.5/4 或 85+/100 才写；排名前 10%–20% 可写「专业前 X%」。
- 核心课程只列与 JD 强相关的 4–8 门，标注「（与岗位相关）」。**这是成本最低的一处ATS 关键词补充**，几乎零收益损失。
- 双学位、交换、荣誉学院可单列一行。
- **入学-毕业起止时间必写**，且与项目、实习的时间线能对上。

### 专业技能（关键，决定匹配度）
- 严格对照 JD 的关键词重写，使简历通过 ATS（招聘系统）筛选。
- 分层：`熟练掌握` / `了解`。禁止整段写「精通」。
- 每条技能挂**证据锚点**：某个项目、某门课、某段实习，用它佐证「掌握程度」这一档。
- 工具链要写到具体：不是「会数据库」，而是「MySQL 建表 / 索引 / 简单调优」。
- 反例与修法：清一色「熟悉 X」让 HR 找不到抓手。把最扎实的那条放「熟练」并挂证据，最弱的放「了解」——诚实且策略正确。

### 项目 / 实践经历（用 STAR + 量化）
每一条按：
- **S（情境）**：什么背景下（课程 / 比赛 / 自驱）
- **T（任务）**：你负责什么
- **A（行动）**：用了什么技术 / 方法
- **R（结果）**：量化产出（性能提升 X%、服务 N 人、获奖等级、Star 数）

**每条 bullet 动词开头，且至少一个数字。** 动词强度标准见 `achievement-writing.md` 第一节。

量化公式（至少满足其一）：
- 数字：用户量、数据量（条/GB）、性能（提升 X%）、精度（达 X%）
- 范围：覆盖 N 个模块、对接 N 个接口
- 等级：获 X 奖、被 X 采用、PR 合入

**时间区间必写**。项目没有起止时间，HR 拉时间线时会把它降级为临时拼凑的作业。

### 校园经历
- 写「做了什么 + 产出」，不要写「认真负责」。例：「策划 X 活动，报名 200+，同比 +30%」。

### 自我评价
- 3 句封顶，句句扣 JD。例：「扎实的 XX 数理基础（绩点 X）；3 段项目验证的工程落地能力；快速学习（2 周自学 XX 并完成 Y）。」
- 不写「吃苦耐劳」「团队合作」这类空话。

## 四、针对性（贴 JD）的硬规则

1. 提取 JD 高频词，确保出现在简历对应板块。
2. 同一份能力，按不同岗位改写表述（投算法突出建模，投开发突出工程）。
3. 每版简历应针对**单一岗位**，不要一份通投所有岗。

## 五、应届生常见失分点

- 把「了解」写成「精通」。
- **项目 / 经历缺起止时间**（HR 拉时间线，无时间即降级）。
- **简历内部前后不一致**——职责声称会某技术，技能栏却没有对应工具或证据，面试一問就穿。
- 经历堆砌无量化、无动词开头；实习写成纯学习记录（全是"学习/整理/辅助"这类弱动词）。
- 板块顺序按时间而非相关度，HR 前 10 秒抓不到重点。
- 自我评价写「吃苦耐劳、团队合作」等空话。
- 一稿多投，不按 JD 改关键词。
- 用花哨模板牺牲可读性 / ATS 兼容。
- **PDF 文字层顺序错乱**：从非 Word 工具导出的 PDF 可能让 ATS 把要点读错位。导出后验证：复制到记事本粘贴，文字顺序应与眼睛看到的一致。

## 六、格式与交付

- 默认产出 **Markdown 简历**（便于编辑、版本管理）+ **HTML 单页简历**（便于打印 / 投递）。
- 一页为佳（A4 一页），内容多可放宽到一页半，不超过两页。
- 文件名：`简历_姓名_目标岗位.md` / `.html`；路线图：`学习路线图_姓名_目标岗位.md`。
