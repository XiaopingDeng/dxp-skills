# 岗位要求（JD）解析方法

把用户给的「岗位要求 / 招聘描述」拆解成结构化需求，作为简历与路线图的共同输入。

## 一、解析目标

从 JD 文本中抽取四类需求，每一类标注「优先级」与「是否在培养方案中覆盖」：

| 类别 | 说明 | 示例 |
|------|------|------|
| 硬技能（Hard） | 具体技术 / 语言 / 框架 | Python、SQL、React、机器学习 |
| 工具 / 平台 | 软件、环境、系统 | Linux、Git、MySQL、Figma、Excel |
| 软技能（Soft） | 通用能力 | 沟通、协作、抗压、文档写作 |
| 证书 / 门槛 | 硬性准入 | CET-6、CPA 通过部分、软考 |

## 二、解析步骤

1. **去噪**：去除公司介绍、福利、泛泛而谈的「有责任心」等。
2. **抽取关键词**：逐句找「要求 / 优先 / 熟悉 / 掌握」后的名词。
3. **分级**：
   - 必需（Must）：出现「要求 / 必须 / 熟悉」
   - 加分（Nice）：出现「优先 / 加分 / 了解」
4. **同义归并**：把「数据结构与算法」「算法」归并；把「数据敏感」归到软技能。
5. **输出技能清单**：`技能名 → 类别 → 优先级 → JD 原文依据`。

## 三、 JD 缺失时的处理

若用户未提供 JD 或 JD 很模糊：
- 询问是否可补充；若不能，调用 `position-requirements-library.md` 中对应岗位的「典型要求」作为默认。
- 在简历与路线图中注明「依据岗位通用要求，建议以实际 JD 为准校准」。

## 四、关键词 → 简历映射

解析结果直接驱动：
- **专业技能板块**：按抽取的关键词重组技能，确保 ATS 命中。
- **学习路线图**：把「必需但未掌握」的技能列为路线图核心项。
- **缺口标注**：在简历对应位置用 `（路线图中补强）` 标注尚未具备的能力，体现诚实与规划。
