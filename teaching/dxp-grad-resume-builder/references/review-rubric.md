# 简历评审规则（指导老师分支）

评审一份**已有**简历原件，产出诊断与建议。核心立场：**诊断 + 建议，不代笔**——原文档零改动，所有改动以「现 / 建议」对照给出。

## 一、评审前：读全原件

**PDF 必须走两步**，缺一步就会误判：

1. **取文字层**：PyMuPDF `page.get_text("text")`，逐页取并自己插页标记。
2. **渲染成图看版面**：`page.get_pixmap(dpi=170)` 出全页图，再按clip 分块 `dpi=300` 放大细看。

为什么两步都要：文字层的**顺序可能与视觉顺序不一致**，且文字层丢失分栏与留白判断。只读文字层，会把排版问题当成结构问题，也会漏掉纯视觉问题（字号过小、间距不均、文本框错位）。

顺带用 `get_text("dict")` 统计字号分布，把「正文字号偏小」这类问题量化出来，而不是凭感觉说"有点挤"。

→ 完成判据：能说出板块数、每个板块的实际视觉顺序、页数、正文字号。

## 二、五个评分维度

总分 100，每维独立赋分。**评分不是重点，定位问题才是**——分数是给学生的行动信号。

| 维度 | 分值 | 看什么 |
|------|------|--------|
| 项目含金量 | 25 | 项目之间是否互补、覆盖不同能力面；有无真实工程细节（不是课程作业能编出来的）；是否对应竞赛/课程/团队的具体出处 |
| 硬技能匹配 | 20 | JD 主干关键词命中；工具链是否写到具体（不是"会数据库"而是"MySQL 建表/索引"）；有无 JD 常见的缺口词 |
| 量化表达 | 20 | 性能、规模、等级三类量化是否到位；有无"极小""提升明显"这类模糊词；职责句里是否一个数字都没有 |
| 完整性与规范 | 20 | 项目有无时间线；获奖有无年份；有无核心课程、GitHub；篇幅是否一页；PDF 文字层是否错乱 |
| 差异化记忆点 | 15 | 有没有属于这个人独有的东西；AI 工具一类新写法是落到产出还是流于罗列 |

## 三、问题定级

每条问题给**级别 + 位置 + 为什么扣分**。级别决定工时分配。

**P0 — 投递前必修**。不改会直接丢分或翻车：
- 项目 / 经历缺时间线（HR 拉时间线，无时间的内容默认降级为临时拼凑）
- 关键指标模糊（尤其当同一段里其他指标已量化时，反差被当成软肋）
- **简历内部前后不一致**（职责声称会某技术，技能栏无对应工具/证据——面试一問就穿）
- 版面硬伤（文字层顺序错乱导致 ATS 解析错位、字号过小、文本框溢出）
- 任何会当场编造才能圆上的表述

**P1 — 显著影响通过率**：
- 经历全是弱动词、零产出（尤其实习：梳理/学习/整理/辅助）
- 技能不分档（清一色"熟悉"，看不出强项）
- 硬技能缺 JD 常见关键词
- 唯一产业经历被埋在项目之后
- 获奖信息量过低（"优秀实验项目"这类）

**P2 — 加分项**：
- 补核心课程、补 GitHub、补自我定位
- 版面细节（照片、邮箱命名、"2027届"归位）
- 若投外企：按 `achievement-writing.md` 的英中惯例差异调整

## 四、给改法的规则

**每条 P0/P1 都要有可直接替换的「现 / 建议」对照。**

- **保留学生真实信息**。改写示范只改表达方式与结构，不替他编内容。
- **量化处留 `[?]`**。要学生自己填实测值，或让他做完后回填。
- **涉及本人才能确认的事标"待核实"**——是否真做过某技术、团队规模、项目归属、是课程还是竞赛。**不要替他填**，这是评审分支最重要的边界。
- **区分"内容弱"与"包装弱"**。技术底子好但没写出来，和真没做过，是两种完全不同的建议。

## 五、追问预判

列出面试官会就简历里的数字与技术细节追问的问题。**每个量化指标都要能被问到**（"误差极小"→ 具体多少、怎么测的；"54 μA"→ 实测还是估算、什么工况）。

同时标出**答不上来就减分**的地方——这类地方要么补数字，要么删掉该指标。

## 六、报告结构

```
标题 + 被评价人/学校/专业/目标岗位 + 综合评分
├─ 总体结论：3 句以内——底子如何、问题在哪、建议动作与预期耗时
├─ 分项评分表：五维得分 + 每维判分依据
├─ P0 清单：每条含位置、问题、为什么扣分、「现/建议」对照
├─ P1 清单：同上
├─ P2 清单：可勾选的加分项
├─ 追问预判表：Q/A 形式，A 里含学生该准备的答案要点
└─ 修改优先级与工时表：顺序 / 动作 / 工时 / 预期收益
```

工时表是给学生的行动清单，按「收益 / 工时」排序，标出哪几项是"今天必须做"的组合。

文末固定声明：**未修改原简历；所有建议需学生核实真实数据后自行执行；任何量化数字不得凭空填写。**

## 七、常见失败点

|症状 | 成因 | 修法|
|------|------|------|
| 只读了 PDF 文字层就下判断 | 漏了版面与顺序核对 | 渲染成图逐块看，比对文字层顺序 |
| 分数给得很低但说不出具体问题 | 评分替代了诊断 | 每个扣分点必须能指向具体位置 |
| 建议里替学生填了技术、技能、数字 | 越界代笔 | 一律标「待核实」，让本人确认 |
| 建议写成"建议加强量化""建议突出重点" | 空话，学生无法执行 | 给出可直接替换的句子 |
| 把"包装弱"当成"内容弱" | 没区分两者 | 先判断技术细节是否真实，再看表达 |
| 罗列一堆问题不给优先级 | 学生不知道先改哪个 | 每条定级，并用工时表排序 |
