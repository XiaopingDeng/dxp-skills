# 撰写分支工作流

从零产出一份可投递的应届生简历 + 学习路线图。规则细节在 `resume-writing-guide.md`（怎么写）、`jd-analysis.md`（拆 JD）、`training-program-mapping.md`（课程映射）、`roadmap-guide.md`（学习卡）；本文件只管**顺序与交接**。

## 一、输入收集的顺序

按「**先要 JD，再问其他**」的顺序问，能显著减少往返：

1. **目标岗位 + JD**（最重要——决定整份简历的关键词方向）。
2. **基本信息**：姓名 / 联系方式 / 城市 / 学校 / 专业 / 入学-毕业时间 / GPA或排名。
3. **培养方案**：课表截图或课程列表。没有就用专业名兜底。
4. **已有素材**：项目、竞赛、实习、获奖。有链接（GitHub / 博客 / 作品）一律要。

**不要一次问十个问题。** 能从上下文推断的先推断，只问真正影响方向的。

**JD 缺失时**：从 `position-requirements-library.md` 取该岗位典型要求，并在简历与路线图里注明「依据岗位通用要求，建议以实际 JD 为准校准」——标注来源，不假装是真实 JD。

**培养方案缺失时**：基于专业名给默认课程映射，标注「默认映射，请以你的真实课表校准」。

## 二、拆解与映射

跑 `jd-analysis.md` 拿到技能清单，跑 `training-program-mapping.md` 拿到对照表。两张表都要留档——它们是简历草稿与路线图之间的桥，也是你回答"为什么这么写"的依据。

匹配度决定文字落点：

| 标记 | 简历里怎么写 | 路线图里 |
|------|-------------|---------|
| ✅ 已覆盖 | 写进技能板块 + 挂项目证据 | 不出现 |
| 🔶 部分 | 写 `了解`，挂课程/项目佐证 | 列为补齐项 |
| ❌ 未覆盖 | 标 `（路线图中补强）` | 核心学习卡 |

**`（路线图中补强）` 是一张承诺**：标了它，路线图里就必须有对应学习卡，否则删掉这个标注。

## 三、起草

按 `resume-writing-guide.md` 的板块顺序：以相关度排序，弱项后置。实习经历如果够强，提到项目之前。

写作规则落在 `resume-writing-guide.md`，这里只强调三条最容易犯的：

1. **动词开头 + 一个数字**。做不到 STAR 全套，至少做到这两样。
2. **技能分档**（熟练 / 了解 / 待补强），把最扎实的证据放最强那档。
3. **一岗一版**：每换一个岗位，重写技能板块的关键词表述，不要只换岗位名。

## 四、渲染

组装模型 JSON（字段见 `scripts/build_resume.py` 顶部 docstring），跑：

```bash
python scripts/build_resume.py <模型.json> --out <输出目录>
```

## 五、交付前自检（不可跳过）

回读产出的每个文件，逐条查：

- [ ] 全文搜不到 `[?]`、`待补充`、`示例，请核对`——有就说明编造内容漏出去了
- [ ] 每个量化数字都能追溯到用户给的真实信息
- [ ] 每个 `（路线图中补强）` 在路线图里有对应学习卡
- [ ] 技能分档与实际掌握程度一致，没有拔高
- [ ] 篇幅一页（内容多可放宽到一页半，不超两页）
- [ ] 板块顺序按相关度而非时间

## 六、常见失败点

| 症状 | 成因 | 修法 |
|------|------|------|
| 一口气问十个问题，用户不回了 | 收集顺序错 | 先要 JD，其余按需追问 |
| 简历所有技能都写"熟练" | 怕显得狂 | 分档，把最弱的放"了解" |
| 一份简历通投多个岗位 | 省事 | 一岗一版，至少重写技能板块 |
| 路线图与简历对不上 | 标了承诺没兑现 | 交付前核对每个 `（路线图中补强）` |
| 交付后用户发现编造内容 | 起草时没标示例 | 量化处留 `[?]` 并标"请核对" |
| 排版按时间顺序而非相关度 | 顺手写成流水账 | 强经历前置，弱项后置 |
