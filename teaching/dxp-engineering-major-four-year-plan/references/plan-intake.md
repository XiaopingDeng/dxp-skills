# 第 1 步：读培养方案

目标只有一个：**把「每门带学分的课 ↔ 它所在的学期」这张映射表拿到手。**
第 2 步的行动表逐学期行，本质就是把这张映射表横过来排版；拿不到映射表，行动表就只能是空话。

## 必须提取到的事实（缺一项就回去找）

| 类别 | 字段 | 用途 |
|---|---|---|
| 身份 | 专业代码、专业名称、学制、授予学位 | 首屏 facts 栏 |
| 体量 | 总学分、课程学分/学时、必修/选修学分占比、实践教学学分占比 | 首屏 facts 栏 + 「一组数字」页 |
| 结构 | 主干学科（通常 3 个）、专业类课程门数、毕业要求条数 | 「说清培养目标」页 |
| **核心** | **每门带学分课程的：名称 · 学分 · 学期** | 逐学期行动表的左两列 |
| 实践 | 集中实践环节名称与学分（认识实习/生产实习/课程设计/毕业设计） | 实习与毕设时点 |
| 特色 | 选修课名里反复出现的那类词 | 见下面「行业特色词」 |
| 加分项 | 通识必修里的数学/物理课名与学期 | 自学清单的对照基准 |
| 加分项 | 有哪些课标注了「AI/智能」「数据」 | 判断「AI+ 课程占比」这类卖点 |

## 三条来源，取法各不相同

### A. 本地 docx / doc / xls（最常见）

**走 `tencent-local-office-edit` 通道**，不要用 python-docx 或 pandoc 硬啃——培养方案的表格式排版很容易让通用解析器吐出乱码。

流程：
1. 先按 `tencent-docs-routing` 路由判定，再加载 `tencent-local-office-edit`。
2. 打开文件后**先拿表格，再考虑段落**：
   - `doc_get_outline` **很可能返回空** `{"items":[]}`——因为培养方案正文通常不用 Heading 样式，全部是手工加粗。这不是失败，是这类文档的常态。
   - **关键路径：`doc_list_tables` → `doc_get_table_info`。** 培养方案里最值钱的内容全在表格里，而 `doc_get_table_info` 返回的是**完整单元格文本**（不截断）。用 `doc_list_tables` 按 `first_row_texts` 认出四张表：
     - `['性质','类别','课程编码','课程名称','学分','考核方式','学时分配','建议选课学期及开课周学时',…]` = **指导性教学计划进程表**（83 行 × 20 列）——课程↔学期↔学分映射的唯一权威来源。
     - `['层次','课程编码','实践环节名称','学分','周数','各学期计划周数',…]` = **集中实践教学环节安排表**。
     - `['学期 / 学时类别','一','二',…]` = 各学期学时分配表（判断哪个学期课业最重）。
     - `['课程性质','课程类别','学时数','学分数','百分比']` = 学时学分结构表（总学分、实践占比的出处）。
   - 把上述表格 dump 成 TSV 网格再读，比逐格看省一半以上来回。
3. **列号必须显式核对，不要按表头数格子**：出表后先打印 `col:值` 形式（只打非空），确认「学期 1」到底是第几列，再读课程学期。合并单元格会让某些行少几格，按位置数会直接错位——这是本环节最容易出的错，会把整门课安到错误学期。
4. **段落全文取不到，这是已知缺陷**：`doc_resolve_document_structure` 的 `mode=compact`、`mode=full`、`text_preview_length=200`、以及 `idx` 定点模式，实测**都只回 ~17 字的截断片段**，拿不到段落全文。`doc_get_outline` 也拿不到正文。
   - 影响：培养目标、毕业要求逐条、学分结构那几段叙述文字会读不全。
   - 处置：**先判断这段信息是否必须**。绝大多数情况下不必——学分结构可从「学时学分结构表」+「课程体系及学时学分比例」段的前半句拿到；毕业要求条数从「本专业…制定了 N 项毕业要求」这一句拿到。
   - 若某段确实必须（如毕业要求逐条内容），用 `doc_find` 返回的 `begin/end` + 上下文 `related_text` 把该句捞出来；仍不够就转来源 B 或直接向用户确认，**不要凭一句半截话编内容**。

**已知坑（都踩过）**：
- **`edsdk.py` 与 skill 目录不在同一处**：`tencent-local-office-edit` 的 SKILL.md 给的 `python3 edsdk.py` 是相对路径，而本机该 skill 实际在 `G:/AIIDE/WorkBuddy/resources/app.asar.unpacked/resources/plugins/workbuddy-builtin/skills/tencent-local-office-edit`。直接 `cd` 到 `~/.workbuddy/skills/...` 会 `No such file or directory`。**每次先确认实际目录再 cd**。
- **临时输出目录要先 mkdir**：把 `doc_*` 的 JSON 重定向到工作区时，输出目录不存在会直接报 `No such file or directory`，且 shell 的重定向失败不会给出清晰提示。先 `mkdir -p`。
- **Windows 路径 + 双引号 JSON 会炸**：`Invalid \escape`。把整个 JSON 用**单引号**包住，反斜杠写成 `\\`。例：
  `'{"path":"E:\\本科生\\...\\培养方案.docx","mode":"compact"}'`。`file_id` 用正斜杠形式（`E:/本科生/.../培养方案.docx`）最稳。
- **预览会改写原文**：编辑器预览把 `data-page-node-id="..."` 注入到标签里。此后任何基于「原文精确串」的编辑都会失配（`String to replace not found`）。所以：**改文件前先重读当前内容**，并且用短而唯一的锚点（一句话尾巴，而不是整个 `<tr>`）。

### B. 课程体系示意图 PNG（docx 啃不动时的救命来源）

**这张图往往比 docx 更好用**：它天然就是「课程 → 学期」的网格，正是我们要的映射表。

- 用 Read 直接读图（多模态），逐学期抄出课程名。
- 抄完后与来源 A 的学分结构对账：把图里的课程数 × 学分累加，看是否逼近培养方案的「课程学分」总数。对不上说明漏抄或看错学期，回去补。
- **A + B 组合是最稳的**：A 给学分/结构/毕业要求，B 给课程↔学期。

### C. 纯文本 / PDF / 用户直接粘贴

- 直接读。PDF 走 pdf 技能抽取。
- 若用户只给了文字没给课程表，**先问**：「有没有课程体系示意图或逐学期课程表？」——没有就不要硬编学期，改为按「基础课在前、专业课在中、实践在后」的通则排，并在行动表里标注「学期以当年教学计划为准」。

## 行业特色词：从选修课名里捞

培养方案里最值钱的信息，往往不在「培养目标」那段官话里，而在**选修课名的重复模式**里。

做法：把选修课名单扫一遍，找出反复出现的一个词族。
- 出现「智能建筑」「楼宇自动化」「建筑设备」「能源管理」→ 特色是 **建筑智能化**
- 出现「工业互联网」「工业控制」「PLC」→ 特色是 **工业物联网**
- 出现「车联网」「车载」→ 特色是 **车联网**
- 出现「医学」「健康监测」→ 特色是 **智慧医疗**

**为什么必做**：这个词直接决定学生的求职坐标。
一个「物联网工程」专业的毕业生，简历投「互联网后端岗」是在跟计算机学院拼刺刀；投「建筑智能化 / 弱电与智能化工程」是在吃本校课程体系的红利。**这句话往往是整份行动表里对学生帮助最大的单点**，要单独成节、加底色强调。

## 完成判据

行动表里要出现的**每一门课程**，都能在提取结果里定位到它的**学期**和**学分**。有课程落不了位，就别开始第 2 步。
