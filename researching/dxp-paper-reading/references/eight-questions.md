# 8 个问题：每一问要抓什么

Griswold 原文列的是 **8 个问题**（文中一处写作 "the above five issues" 是早期版本残留，
以 8 个为准，别被它绕晕）。

靠前的是**提取**，靠后的是**你自己的分析**——这条分界决定了哪几问允许、甚至必须
出现作者没有说过的内容：

| 问题 | 性质 | 允许复述作者吗 |
|---|---|---|
| Q1 动机 · Q2 方案 · Q3 评估 · Q5 贡献 · Q6 未来方向 | 提取 | 允许，但仍要落到原文定位 |
| Q4 你的分析 · Q7 遗留问题 · Q8 take-away | 分析 | 复述即失败 |

---

## Q1 动机 motivation

**要抓三层，一层都不能少：**

- **people problem** —— 世界层面想要的好处：省时、更安全、更省人力。论文常常不显式写，
  从引言的场景描述里提取。
- **technical problem** —— 为什么这件事没有平凡解。**这层最常被漏掉，却是判断论文价值的关键。**
- **research question** —— 作者最终收敛出的那个具体问题，可能比开篇的问题窄得多。
- 外加一件：**已有方案是什么、为什么不够**。

**去哪找**：引言（§1）、Related Work 的前两段、摘要里的动机句。

**好答案**：「传感器节点数据量大 → 想省下行传输量（people）；但压缩恰恰会削掉罕见事件，
而罕见事件是告警的唯一依据，所以不能简单地全压（technical）；论文问的是：能否在保住罕见事件
可检测性的前提下压到 1/10（RQ）。作者认为已有的自适应采样在样本极少时估计不稳。」

**差答案**：「本文研究了传感器网络中的数据压缩问题。」——这是复述标题。

**坑**：把 people problem 当 technical problem 写（「提升效率」不是 technical problem）；
把摘要第一句当 RQ。

## Q2 方案 solution / hypothesis / idea

**要抓：**

- 对 RQ 的**具体回答** —— 核心机制，一到两句能讲清的东西。
- **为什么相信它可行、且优于已有方案。** 这一条经常被作者写得含糊，值得单独标出来。
- 关键取舍：怎么做到的、代价是什么。
- 把 idea 与 implementation 分开写。有些论文的贡献是 idea，实现只是证据。

**去哪找**：引言末尾的「本文贡献」段（往往全文最浓缩）、方案章的第一个小节、Figure 1 的 caption。

**坑**：把流程细节当方案（「先用 A 处理再用 B 训练」是实现，不是 idea）；把 idea 写成
「我们提出了一个基于深度学习的框架」——那不是 idea，是模板句。

## Q3 评估 evaluation

**要抓：**

- 用什么证明了 idea 有价值：论证 / 实现 / 实验，是哪一种或哪几种。
- **baseline 是谁、数据集是什么、指标是什么** —— 三个都要落名。
- 关键数字用原文的表述与量级，不要自己换算或四舍五入。
- 作者自己承认的收益与问题。

**去哪找**：实验章的 setup 小节、主结果表、Discussion / Limitations。

**坑**：只写「实验证明了方法的有效性」。没有 baseline、没有数字、没有指标的评估不成立。
主张与评估对不上（RQ 问 A、实验只测了 B）时——那不是坑，是发现，写进 Q4。

## Q4 你的分析

**这一问禁止复述作者。**

**要抓：**

- 这是好 idea 吗？给出判断的理由，不要只给结论。
- **至少一条作者没有明说的东西**：隐含前提、未验证的假设、结论会被推翻的条件。
- 最有意思的点、最有争议的点——各一条，争议那条要说清「争议在哪」。
- 有实践指向时：真能落地吗？谁会要？交付需要什么？什么时候可能成真？

**好答案**：「方法依赖标签分布在时间上平稳，而 §3.2 承认测试集与训练集同源——换到跨域场景，
作者给的机制没有理由继续成立。全文没有把这个前提列为 limitation。」

**差答案**：「该方法创新性较强，但也存在一定局限性。」——零信息。

**坑**：把「局限」写成方法论套话；不敢给负面判断（Griswold 明确要求你找 flaws）；
挑一个没人会反对的点当「最有争议」。

## Q5 贡献 contributions

**要抓**：把贡献**分类**列出来——洞见/idea、软件或数据集、实验技术或评测方法、领域综述。
然后与作者自述的 contribution 列表对照：**作者声称的与实做到的是否一致？**

**坑**：照抄结论里的 contribution bullet。要落到具体产物（「一个 10 万条标注的数据集」），
而不是「推动了该领域的发展」。

## Q6 未来方向

**要抓两条线：**

1. **作者指出的** —— 通常在结论或 Future Work 段。
2. **你读出来的** —— 作者当作理所当然却值得追问的，以及 Q4 那些缺陷自然引出的方向。

**坑**：只抄作者的 Future Work。第二条线空着，说明你只在摘，没在读。

## Q7 遗留问题

**要抓**：讨论时你会抛出的问题；你觉得含糊、难懂、或者「似乎是错的」的地方。
**不少于 3 条，每条都具体可回答**，并且指认它针对哪一处（某个假设、某个实验设置、某段推导）。

Q4 与 Q7 的分工：**Q4 是已经形成的判断，Q7 是还没有结论的疑问。** 不要把 Q4 的批评搬过来充数。

**好答案**：「§4.3 的消融只去掉了模块 A，但 A 与 B 在实现上共享同一层特征——怎么确认涨点来自 A？」
**差答案**：「部分公式的推导较难理解。」——没有指向，无法回答。

## Q8 take-away message

**要抓**：一句话，从**你的视角**说清这篇论文的主要含义——它改变了什么、谁该关心。

**约束**：不得出现论文标题或摘要里的原句。出现即视为复述。

**坑**：写成「本文提出了一种 xxx 方法，在 xxx 上取得了 xxx 的结果」——那是摘要压缩，
不是 take-away。

## 复核清单（Step 4 的 Done when）

八条都要能打勾，任一条不合格就回去补，不要带着缺口进 Step 5。

- [ ] Q1 三层齐全：people problem / technical problem / research question，另加已有方案为何不足
- [ ] Q2 的「为什么可行、为什么更好」有实质内容，不是「因为设计合理」
- [ ] Q2 把 idea 与 implementation 分开写了
- [ ] Q3 的 baseline、数据集、指标三个都落名，关键数字来自原文
- [ ] Q4 至少一条是作者未明说的，且不是套话
- [ ] Q4 的「最有争议的点」说清了争议在哪
- [ ] Q6 两条线都在：作者指出的 + 你读出来的
- [ ] Q7 不少于 3 条，每条带指向，且与 Q4 的批评不重复
- [ ] Q8 只有一句话，且没有标题/摘要的原句
- [ ] Q1–Q6 每个答案都有原文定位；Q7 每条都指认了针对的位置
- [ ] 缺内容的地方写的是「原文未提供」，没有用常识补齐
