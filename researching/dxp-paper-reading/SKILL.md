# PDF 论文 → 逐篇结构化阅读笔记

输入 N 篇 PDF，输出 N 份 Markdown 笔记，每份回答同样 8 个问题。方法出自
William G. Griswold, *How to Read an Engineering Research Paper* (UCSD CSE210)：
论文在不同粒度上重复（引言给高层动机与方案、正文给细节、结论再收一遍），
所以读法和写法都允许乱序——**先拿到全篇骨架，再逐问回填**。

## 管线

| # | 步骤 | Done when |
|---|---|---|
| 1 | 建账 | 待读清单里每一项都是真实存在、可打开的 PDF；数量与用户给的一致 |
| 2 | 通读取文 | 每篇都有一份 `.extracted.txt`，脚本的 health 行没有告警，且你已通读 |
| 3 | 结构地图 | 8 个问题各自指认到原文章节，或明确标注「原文未提供」 |
| 4 | 逐问凝练 | 8 问全部有答案，且通过 `references/eight-questions.md` 末尾的复核清单 |
| 5 | 成稿 | 每篇一个 `.md` 已写出；一级标题与模板逐一对应；无残留占位符 |

Step 2–5 是**逐篇循环**：一篇走完 2→5，再走下一篇。

先读完本文件——它是地图。每一步只带自己的硬规则，细节指向 references / assets。

## 硬规则（每次运行都成立）

1. **一篇一文件。** 用户给 N 篇就是 N 份笔记，不合并成一份总笔记（用户明确要合稿时除外）。
2. **每个答案都要落回原文。** Q1–Q3、Q5、Q6 的答案末尾给出定位；Q4 的每条判断也要指向它依据的
   位置；Q7 的每个问题要指认它针对哪一处。用 `§4.2` / `Fig. 3` / `Table 2` 这种形式，有页码就带页码。
3. **区分「原文说的」和「你判断的」。** Q1–Q3、Q5、Q6 是提取，Q4、Q7、Q8 是你的分析。
   Q4 里出现作者的结论就是抄——它必须给出作者**没有**明说的东西：隐含前提、未验证的假设、落地条件。
4. **没写就是没写。** 论文缺的东西（没做用户研究、没给消融、没谈代价）写「原文未提供」。
   用领域常识补一个看起来完整的答案是这份笔记最严重的失败模式。
5. **不修改输入 PDF。** 只读。产物只有 `.md`。
6. **笔记用中文写，术语留英文。** 关键术语首次出现给中英对照；引用作者原话用英文原句加引号。
   用户另有要求时以用户为准。

## 读法

先**扫一遍全文拿骨架**，再对着 8 个问题回头找证据——不要顺着读到底、边读边写。
Griswold 反复强调：**不能回答完这 8 个问题，就不算读完。**

写完最后一问后回头再扫一遍。第一遍读出来的答案经常在第二遍被推翻，尤其是
Q1 的 technical problem 和 Q2 的「为什么它可行」。

## Step 1 — 建账

把用户给的输入（文件路径、通配、整个目录）解析成一份待读清单：文件路径 + 从文件名猜的标题。

- 目录输入 → 取其中的 `*.pdf`；清单为空就停下问用户，不要自己换目录去找。
- 用户给的是链接或非 PDF 文件 → 先拿到本地 PDF 再进管线，并在回复里说明做过转换。
  不要默默把 HTML / Word 当 PDF 走完流程。
- 清单打印出来再往下做：数量对不对、有没有重名。

## Step 2 — 通读取文

**不要用 Read 直接读 PDF** —— Read 按扩展名把它判成二进制文件拒掉。先用技能自带的
`scripts/extract_pdf.py` 抽成带页码的文本：

```bash
D:/dev/Python/Python312/python.exe scripts/extract_pdf.py <paper.pdf>
```

产物是 `<paper>.extracted.txt`，每页一个 `===== PAGE n =====` 分隔符，页码就是笔记的锚点之一。

脚本要跑在**装了 PyMuPDF 的解释器**上：本机用 `D:\dev\Python\Python312\python.exe`；
托管解释器只有 openpyxl，会 `ModuleNotFoundError: fitz`。

然后 Read 那份 dump 通读全文（一篇要读全，不要只读引言和结论就动笔）。看脚本 stdout 的
`health` 行：

- **报「空格丢失」** → 换引擎重抽。这种 dump 里 `Providedproperattributionisprovided`
  连成一片，写进笔记的引用全是错的，必须先修好再读。
- **报「疑似扫描件」** → 没有文本层。走 OCR（`pdf` / `pdfkit-py` 技能），或告诉用户这份 PDF
  需要带文本层的版本。不要靠猜补内容。

读的时候两个正常现象不要当成故障：**章节号常单独占一行**（编号和标题是两个文本块），
读成 `§3.1` 就行；**表格会拆成一格一行**，引用时用表号加原文表述，不要自己把表格拼回来。

超长论文（>30 页）分段读：先引言 + 结论 + 每节末段拿骨架，再回填需要的细节。

取文仍然不对时查 `references/pdf-extraction.md`：故障 → 原因 → 修法的对应表。

## Step 3 — 结构地图

对每篇写一张清单（工作稿，不必进笔记）：标题 / 年份与出处（若有）/ 有哪些章节 /
8 个问题分别在哪。

Griswold 的经验分布是：动机在引言；方案与评估的高层面陈述在引言与结论；
未来工作在结尾；方案与评估的细节在正文。**与这个分布不符的地方值得记一笔**，
它往往是这篇论文的结构特点。

指认不出某一问的出处时，就地写「原文未提供」，不要留空等后面补。

## Step 4 — 逐问凝练

动笔前读 `references/eight-questions.md`。它给出每一问的子问题、去哪找、
好答案与差答案的分界，以及末尾的复核清单（Step 4 的 Done when 就是它）。

拿不准该写到什么深度时，对照 `assets/example-note.md`——一篇真实论文的成稿。

多篇论文时，**第一篇写完先照一遍复核清单再写第二篇**：清单上的缺口集中在 Q4 和 Q7，
这两处最容易滑回复述。

## Step 5 — 成稿

照 `assets/reading-note-template.md` 写，一篇一份，默认落到输入 PDF 所在目录：

```
<PDF 所在目录>/reading-notes/<PDF 主文件名>.md
```

用户指定了输出目录或文件名就按用户的。扩展名 `.md` 不能省。
不同目录下同名 PDF 撞名时，在后一份的文件名后加 `-2`、`-3`，并在笔记头部注明原路径。

模板的一级标题不要增删；占位符（方括号）全部替换掉，一个都不留。

## 收尾

- 回复里报出每篇笔记的路径 + 一句话结论（用该篇的 take-away）。
- 明确指出哪些答案是「原文未提供」或推断出来的——这是用户最需要知道的部分。
- 若某篇 PDF 是扫描件或读不全，单独说明，别混在成功列表里。
